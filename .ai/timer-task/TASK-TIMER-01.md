# TASK-TIMER-01 — 학생 공부시간 Timer / 간편 기록 UI

## 1. Task 개요

### 목적
중·고등학생이 공부 시간을 **최소한의 조작으로 기록**할 수 있도록 모바일 중심의 Timer 화면을 구현한다.

기존 기획의 뽀모도로, 일반 스톱워치, 사후 시간 보정 기능을 유지하면서 학생이 실제 사용 시 가장 빠르게 기록할 수 있는 UI를 제공한다.

### 기술 환경

- Frontend: React
- UI: 모바일 반응형 Web UI
- Frontend URL: `http://localhost:3000`
- Backend: Spring API
- Backend URL: `http://localhost:8080`
- 기존 학습 기록 API 및 DB 구조 활용
- 기존 `study_sessions`의 `STOPWATCH`, `POMODORO_FOCUS`, `MANUAL` 모드 활용

### 참고 기획
- 기존 타이머 기획의 뽀모도로 / 스톱워치 / 사후 보정 기능
- 타임스탬프 기반 시간 계산
- Wake Lock
- 모바일 백그라운드 대응
- 네트워크 단절 시 재전송
- 과목별 공부시간 누적

---

# 2. 핵심 UX 목표

학생이 앱을 열었을 때 다음 3가지 행동을 가장 빠르게 수행할 수 있어야 한다.

1. **지금 공부 시작**
2. **공부한 시간을 빠르게 추가**
3. **오늘 공부한 시간을 바로 확인**

학생에게 복잡한 관리 기능을 노출하지 않고, 핵심 행동을 중심으로 구성한다.

# 4. Timer 모드

## 4.1 일반 스톱워치

학생이 원하는 만큼 공부한 후 직접 종료한다.

### 상태

```text
IDLE
 ↓
RUNNING
 ↓
PAUSED
 ↓
COMPLETED
```

### UI

```text
┌───────────────────────────────┐
│             수학               │
│                               │
│          01:32:45             │
│                               │
│       [ ⏸ 일시정지 ]           │
│       [ ■ 공부 종료 ]          │
└───────────────────────────────┘
```

### 요구사항

- 시작 시 서버 세션 생성
- 실제 시간은 `start_time` / 현재 시각 차이로 계산
- `setInterval`은 화면 표시용으로만 사용
- 백그라운드 복귀 시 현재 시각 기준으로 즉시 재계산
- 종료 시 서버에 실제 공부시간 저장
- 중도 종료 시 사용자가 저장 여부를 확인할 수 있도록 처리

# 6. 빠른 공부시간 입력

## 6.1 원터치 추가

현재 선택된 과목에 바로 시간을 누적한다.

```text

```

### 동작

예:

현재 과목 = 수학

`+30분` 클릭

→ `MANUAL` 세션 생성

→ 수학 공부시간에 30분 추가

→ 오늘 누적시간 즉시 갱신

→ 성공 Toast 표시

```text
✓ 수학 공부시간 30분이 추가되었습니다.
```

# 10. 백그라운드 / 절전 대응

기존 기획의 타임스탬프 기반 계산 방식을 적용한다.

## 중요

`setInterval`의 경과 횟수를 이용해 실제 공부시간을 계산하지 않는다.

실제 시간은 다음 기준으로 계산한다.

```text
elapsed =
  currentTimestamp - sessionStartTimestamp
```

따라서 모바일 브라우저가 백그라운드에서 Timer 실행을 제한하더라도 복귀 시 정확한 시간을 재계산한다.

### 복귀 처리

```text
앱 활성화
 ↓
현재 시각 확인
 ↓
세션 시작 시각과 차이 계산
 ↓
Timer 화면 갱신
 ↓
필요한 경우 서버 상태 확인
```

---

# 11. Wake Lock

지원 브라우저에서는 공부 시작 시 화면 꺼짐 방지를 요청한다.

```javascript
navigator.wakeLock.request('screen')
```

미지원 환경에서는 다음 안내를 표시한다.

```text
화면 자동 꺼짐 방지를 지원하지 않는 브라우저입니다.
기기 설정에서 화면 자동 꺼짐 시간을 길게 설정해주세요.
```

# 12. 브라우저 새로고침 / 재접속

활성 세션 정보를 로컬에 저장한다.

예:

```json
{
  "sessionId": "uuid",
  "subjectId": "uuid",
  "startTime": "2026-09-28T19:00:00+09:00",
  "mode": "STOPWATCH"
}
```

재접속 시 활성 세션이 존재하면 다음 화면을 표시한다.

```text
이전에 진행 중인 공부가 있습니다.

수학
01:23:40

[ 이어서 진행 ] [ 종료하고 저장 ]
```

# 13. 네트워크 오류 대응

공부 종료 API가 네트워크 문제로 실패하더라도 기록을 즉시 잃지 않도록 한다.

## 처리

```text
세션 종료
 ↓
API 요청
 ↓
성공 → 완료
 ↓
실패
 ↓
로컬 Queue 저장
 ↓
네트워크 복구
 ↓
API 재전송
```

재전송 성공 후 Queue에서 제거한다.

# 18. Acceptance Criteria

- [ ] 과목을 선택할 수 있다.

- [ ] 실제 공부시간이 서버에 저장된다.

- [ ] `+10분` 버튼이 동작한다.
- [ ] `+30분` 버튼이 동작한다.
- [ ] `+1시간` 버튼이 동작한다.
- [ ] 현재 선택된 과목에 시간이 누적된다.

- [ ] Bottom Sheet가 열린다.
- [ ] 과목을 선택할 수 있다.
- [ ] 시간/분을 입력할 수 있다.

```text
→ 서버 재전송
→ 정상 기록
```

# 21. 구현 시 주의사항

1. 클라이언트의 `duration_sec`만 무조건 신뢰하지 말고 서버에서 세션의 유효성을 검증한다.
2. 동일 세션의 종료 요청이 여러 번 들어와도 중복 기록되지 않도록 한다.
3. 시간 계산은 타임스탬프 기반으로 처리한다.
4. 휴식 시간은 순공 시간에 포함하지 않는다.
5. 학생이 빠르게 기록할 수 있는 UX를 우선한다.
6. Timer 화면과 관리자/확인자용 데이터 관리 화면의 UI를 분리한다.
7. 학생용 Timer 화면에서는 ag-Grid를 사용하지 않고 카드/버튼 중심 UI를 사용한다.
8. 기존 `study_sessions` 및 API와 충돌하지 않도록 기존 계약을 우선 확인한 후 구현한다.
