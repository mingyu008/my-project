# 일정관리 보안 요구사항

## 1. 인증
모든 일정 API는 기존 인증 체계를 사용한다.

## 2. 권한 검증
클라이언트가 보낸 사용자 ID를 신뢰하지 않는다.
현재 로그인 사용자 정보를 서버의 인증 컨텍스트에서 가져온다.

## 3. IDOR 방지
예:
`PUT /api/schedules/100`

현재 사용자가 100번 일정의 수정 권한을 가지고 있는지 서버에서 확인한다.

## 4. 입력값 검증
Spring Validation을 사용한다.
예:
- `@NotBlank`
- `@Size`
- `@NotNull`
- 커스텀 날짜 범위 검증

## 5. XSS
설명/장소 등 사용자 입력을 HTML로 직접 렌더링하지 않는다.
HTML이 허용되지 않는 경우 일반 문자열로 처리한다.

## 6. SQL Injection
JPA/Prepared Statement 기반으로 처리한다.
문자열 SQL을 직접 연결하지 않는다.

## 7. CSRF/CORS
React `localhost:3000` -> Spring `localhost:8080` 개발환경을 고려하여 CORS를 설정한다.

운영환경에서는 허용 Origin을 실제 프론트엔드 도메인으로 제한한다.

## 8. 에러 정보
내부 SQL, Stack Trace, 파일 경로 등 민감한 정보를 클라이언트에 노출하지 않는다.

## 9. 감사 정보
등록자/등록일/수정자/수정일을 서버에서 기록한다.
클라이언트가 임의로 해당 값을 지정하지 못하게 한다.
