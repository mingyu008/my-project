# 일정관리 업무 규칙

## 1. 필수값
- title: 1~200자
- startAt: 필수
- endAt: 필수
- status: 허용된 코드만
- priority: 허용된 코드만

## 2. 기간 검증
`startAt <= endAt`

허용하지 않음:
- 종료 < 시작

동일 시각의 시작/종료를 허용할지 여부는 프로젝트 정책으로 결정한다.
MVP에서는 허용한다.

## 3. 권한
- 일반 사용자는 기본적으로 자신의 일정만 수정/삭제.
- 관리자는 전체 일정 수정/삭제.
- 서버가 최종 권한을 검증한다.

## 4. 공개 여부
`isPublic=true`라도 인증이 필요한 시스템이라면 실제 접근 권한 정책을 별도로 적용한다.

## 5. 삭제
논리 삭제를 기본으로 한다.
삭제된 일정은 일반 목록에서 제외한다.

## 6. 중복 일정
동일 담당자에 대해 다음 조건이면 겹침으로 판단한다.

`existing.startAt < new.endAt`
AND
`existing.endAt > new.startAt`

수정 시 자기 자신의 ID는 제외한다.

## 7. 상태 전이
기본 허용:
- PLANNED -> IN_PROGRESS
- PLANNED -> CANCELLED
- IN_PROGRESS -> COMPLETED
- IN_PROGRESS -> CANCELLED

필요하면 관리자에게 상태 강제 변경 권한을 제공한다.

## 8. 시간대
- API는 ISO-8601 형식을 사용한다.
- 운영 서버와 DB의 시간대 정책을 명확히 설정한다.
- 다국가 서비스가 아니라면 한국 표준시(Asia/Seoul)를 기준으로 운영할 수 있다.

## 9. 제목 검색
기본적으로 부분 일치 검색을 제공한다.
대소문자/한글 검색 정책은 DB 및 검색 방식에 맞춘다.
