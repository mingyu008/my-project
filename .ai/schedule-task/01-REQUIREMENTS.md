# 일정관리 게시판 기능 요구사항

## 1. 목적
사용자가 업무 일정을 등록하고 조회/검색/수정/삭제할 수 있도록 한다.

## 2. 사용자 유형
| 역할 | 주요 권한 |
|---|---|
| 일반 사용자 | 본인이 등록한 일정 조회/등록/수정/삭제 |
| 관리자 | 전체 일정 조회/등록/수정/삭제 |
| 읽기 사용자 | 일정 조회만 가능 |

> 실제 권한 코드는 기존 인증/권한 체계에 맞춘다.

## 3. 일정 데이터
필수:
- 일정 제목
- 시작 일시
- 종료 일시
- 일정 상태
- 우선순위

선택:
- 설명
- 장소
- 담당자
- 공개 여부
- 색상

## 4. 기능 요구사항

### FR-01 목록 조회
- 일정 목록을 AG Grid로 표시한다.
- 기본 정렬: 시작 일시 내림차순.
- 페이지네이션 또는 서버 사이드 조회를 지원한다.
- 컬럼:
  - ID
  - 제목
  - 시작 일시
  - 종료 일시
  - 상태
  - 우선순위
  - 담당자
  - 장소
  - 등록자
  - 등록일

### FR-02 검색
다음 조건을 조합하여 검색할 수 있다.
- 제목
- 기간
- 상태
- 우선순위
- 담당자
- 등록자

검색 조건은 서버 API에 전달한다.

### FR-03 등록
- 일정 등록 버튼 제공.
- 필수값 검증.
- 종료 일시는 시작 일시보다 빠를 수 없다.
- 등록 성공 후 목록을 갱신한다.

### FR-04 상세
- 목록에서 행을 선택하면 상세 화면 또는 상세 모달을 연다.
- 일정의 전체 정보를 표시한다.

### FR-05 수정
- 작성자 또는 관리자만 수정 가능.
- 수정 성공 후 목록과 상세 정보를 갱신한다.

### FR-06 삭제
- 작성자 또는 관리자만 삭제 가능.
- 삭제 전 확인창을 표시한다.
- 가능하면 물리 삭제보다 논리 삭제를 기본으로 한다.

### FR-07 상태
기본 상태:
- `PLANNED`: 예정
- `IN_PROGRESS`: 진행중
- `COMPLETED`: 완료
- `CANCELLED`: 취소

### FR-08 우선순위
- `LOW`
- `NORMAL`
- `HIGH`
- `URGENT`

### FR-09 중복 확인
동일 담당자의 시간대가 겹치는 일정이 있는 경우 경고한다.
- 기본 정책: 저장 자체를 막지 않고 경고
- 관리 정책에 따라 차후 차단으로 변경 가능

### FR-10 반응형
- 데스크톱 우선
- 태블릿에서도 주요 기능 사용 가능
- AG Grid 컬럼은 화면 폭에 따라 숨김/축소한다.

## 5. 비기능 요구사항
- 모든 API는 인증 상태를 확인한다.
- 서버에서 최종 권한 검사를 수행한다.
- 날짜/시간은 서버 기준 정책을 명확히 한다.
- SQL Injection, XSS, CSRF 등 일반적인 웹 보안 요구사항을 준수한다.
- 목록 API는 과도한 데이터 조회를 방지한다.

## 6. MVP 제외
- 반복 일정
- 참석자 초대
- 이메일/SMS/푸시 알림
- 외부 캘린더 연동
- 첨부파일
- 댓글
